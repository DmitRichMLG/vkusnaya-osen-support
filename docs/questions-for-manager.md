# Вопросы менеджеру и временные допущения

Менеджер проекта отвечает в Telegram (@ReshTatyana) по будним дням с 9:00 до 18:00. Пока ответа нет, работаем по временному допущению из строки «Пока делаем так».
Каждое временное допущение попадёт и в README → «Допущения»; после ответа меняем код, эталон и README.

## Отправить сейчас

### 1. Статистика: что считать вопросом и куда относить отказы
**Вопрос:** Статистику «бот закрыл сам / передал операторам» считаем по сообщениям участников или по обращениям? Входят ли отказы (офтоп, попытки взлома) в «закрыл сам»?
**Почему важно:** По этим процентам клиент будет судить о пользе бота. Бот отвечает без обращения, а в одно обращение дописываются несколько сообщений, так что единица счёта меняет цифры. Если включить отказы в «закрыл сам», метрику накрутят тролли, а ошибочный отказ спрячется среди успехов.
**Варианты:** а) по сообщениям, отказы отдельной строкой (предлагаем); б) по сообщениям, отказы входят в «закрыл сам»; в) по диалогам (серия сообщений с паузой меньше 30 минут); г) «закрыл сам» — в сообщениях, «передано» — в обращениях, без процентов.
**Пока делаем так:** Единица — входящее сообщение, по которому бот принял решение; /start, приветствия и «спасибо» без вопроса, дубли от Telegram и медиа без текста не считаем. Три категории, в сумме 100%: «ответил сам» (ответ прошёл проверку пунктов и отправлен), «передано оператору» (с разбивкой: решение модели, из них с частичным ответом; сбой ИИ; не прошла проверка пунктов; новое обращение или дописано в открытое), «отказ» («не по теме» / «манипуляция»). «Бот закрыл сам» — только первая категория, рядом цифра «без участия оператора» = ответил + отказ. Отдельно — обращения: создано, закрыто, ждут ответа.
**Если ответ другой:** Всё считается из журнала решений бота — меняются только запросы статистики, схема базы не меняется.

### 2. Время ответа оператора: рабочие или календарные часы
**Вопрос:** Среднее время ответа оператора считаем в рабочих часах (будни 9:00–18:00 МСК) или в календарных? Какая цифра для клиента главная?
**Почему важно:** Вопрос передан в пятницу в 18:30, ответ дан в понедельник в 9:30: это 0,5 рабочего часа, но 63 календарных. Календарные часы смешивают скорость операторов с их графиком (12.1), рабочие не показывают, сколько ждал участник.
**Варианты:** а) обе цифры, главная — рабочие часы (предлагаем); б) только рабочие; в) только календарные.
**Пока делаем так:** Время первого ответа: от создания обращения до первого ответа оператора из панели. Показываем обе цифры, главная — рабочие часы (04.11.2026 — нерабочий). Обращения без ответа в среднее не входят — отдельная строка «ждут ответа: N, самое давнее — X ч».
**Если ответ другой:** Меняются расчёт и подписи: все отметки времени уже хранятся (timestamptz).

### 3. Бот при открытом обращении (решено нами)
**Вопрос:** Сообщаем о принятом решении: пока у участника открыто обращение, бот сам отвечает на типовые вопросы по правилам, а всё, что требует оператора, дописывает в это же обращение. Вас это устраивает?
**Почему важно:** Клиент хочет, чтобы бот закрывал типовые вопросы сам, потому что операторы не успевают. Если на время открытого обращения всё слать оператору, типовые вопросы снова пойдут в перегруженную очередь, а участник будет ждать — иногда все выходные — ответ, который бот мог дать сразу.
**Варианты:** а) бот отвечает на типовое сам, остальное дописывает в открытое обращение (принято); б) пока обращение открыто, всё дописывается в него, бот только подтверждает передачу.
**Пока делаем так:** Решение уже принято нами — по задаче клиента (разгрузить операторов) и правилу «у участника одно открытое обращение». Бот отвечает на вопросы по правилам сам; всё, что требует оператора, дописывается в то же обращение, и участник снова получает фразу о сроке ответа. Уточнения по теме обращения, ответы на вопросы оператора и «ну что там?» бот не закрывает, а дописывает. Модель видит суть открытого обращения и последние сообщения, включая ответы оператора; ответы бота видны в истории обращения.
**Если ответ другой:** Вариант б — одна ветка в обработчике (дописывать без вызова модели); доля «закрыл сам» упадёт, нагрузка на операторов вырастет.

### 4. Какой срок ответа обещать участнику
**Вопрос:** Есть ли срок ответа операторов (SLA), который можно обещать участнику, или называем только часы работы из 12.1?
**Почему важно:** Фраза о сроке добавляется к каждой передаче. Обещание «ответим в течение часа» при перегруженных операторах вызовет новые жалобы.
**Варианты:** а) без срока: часы работы и начало ближайшей смены (предлагаем); б) «в течение рабочего дня»; в) «в течение N рабочих часов».
**Пока делаем так:** Фразу считает код по 12.1 (будни 9:00–18:00 МСК, 04.11 нерабочий), модель срок не пишет. В смену: «Операторы сейчас на смене (по будням с 9:00 до 18:00 МСК) — ответ придёт сюда, в этот чат». Вне смены: «…вернутся в понедельник, 12 октября, в 9:00 — ответ придёт сюда» (дату подставляет код).
**Если ответ другой:** Меняется шаблон фразы; при SLA — подсветка просроченных обращений и доля ответов в срок.

### 5. Видят ли операторы данные участника на сайте
**Вопрос:** Видят ли операторы в админке сайта чеки, статусы, победителей и доставку участника? Ищут ли его по номеру телефона?
**Почему важно:** «Где мой приз», «почему отклонили чек», «участвую ли я» (№14, 16, 17, 18, 21, 22) бот передаёт оператору, потому что сам базу не видит. Если оператор тоже не видит, передача бесполезна; от ключа поиска зависит, что бот спросит у участника.
**Варианты:** а) да, по номеру телефона (предлагаем); б) по другому ключу — какому?; в) доступа нет, запросы идут организатору.
**Пока делаем так:** Доступ есть, поиск по номеру (5.2). В личных вопросах бот просит номер, на который зарегистрирован кабинет; карты, пароли и коды из SMS не просит никогда (11.2).
**Если ответ другой:** Другой ключ — меняется текст запроса; нет доступа — статус «ждём организатора» и другая фраза о сроке.

### 6. Повторная регистрация отклонённого чека
**Вопрос:** Если чек отклонили из-за ошибки ручного ввода или лимита 10 чеков в сутки, можно ли зарегистрировать его заново, или он отклонится как повторный (6.2)?
**Почему важно:** В №21 пишут «третий раз не принимаете». Если повтор разрешён, бот сам подскажет исправить данные или отсканировать QR-код (5.3); если нет — такой совет навредит.
**Варианты:** а) можно в обоих случаях; б) только после ошибки ввода; в) нельзя, решает оператор.
**Пока делаем так:** Бот не советует загружать отклонённый чек снова: причина — в «Мои чеки» (6.4), возможные причины — 6.5, конкретный чек — оператору.
**Если ответ другой:** Ответ станет пронумерованным уточнением (см. 8), бот ответит сам; меняется эталон для №21.

### 7. Чек, оплаченный другим человеком
**Вопрос:** Можно ли зарегистрировать на свой номер чек, который оплатил другой человек (например, мама)?
**Почему важно:** Это №12, семейные покупки — частый случай. Прямого ответа нет: 5.1 описывает покупку как шаг участия, 5.2 — «один номер — один участник», 6.2 — чек один раз, в 6.5 «чужого» чека нет. От ответа зависит, кому достанется приз и что будет при запросе оригинала (6.6).
**Варианты:** а) можно, участник — владелец номера; б) нельзя, только свои покупки; в) решает оператор.
**Пока делаем так:** Частичный ответ + оператор: участник и получатель приза — владелец номера, мама может участвовать со своего номера, чек регистрируется один раз; «можно ли» — оператору.
**Если ответ другой:** Добавим уточнение, бот будет отвечать сам; меняется эталон для №12.

### 8. Вопросы, ответа на которые нет в правилах
**Вопрос:** Есть ли согласованные ответы (FAQ) на вопросы вне правил — будут ли акции дальше, сколько участников (и можно ли это называть), какой маркетплейс у сертификата? Или бот может закрывать их сам фразой «в правилах этого нет», без оператора?
**Почему важно:** На такие вопросы у операторов, скорее всего, тоже нет ответа, и в перегруженную очередь попадают пустые обращения (№13, 15). Ответы менеджера бот сможет использовать, только если они пронумерованы — иначе проверка ссылок их отклонит.
**Варианты:** а) FAQ нет, всё вне правил — оператору (сейчас так); б) пришлём FAQ; в) бот сам отвечает «информации пока нет».
**Пока делаем так:** Бот отвечает той частью, что есть в правилах (№13 — сроки 2.2 и 2.3, №15 — механика 5.5 и 8.4), остальное — оператору. Ответы менеджера складываем в файл уточнений (У1, У2…): модель видит его с правилами, код проверяет ссылки на него как на пункты.
**Если ответ другой:** Б — FAQ в файл уточнений и перепрогон; в — отдельный тип ответа без пунктов и обращения, меняется эталон для №13 и 15.

## Можно позже

### 9. Просьба позвать живого оператора
**Вопрос:** Если участник прямо просит «позовите человека», создаём обращение сразу, даже если вопрос типовой?
**Почему важно:** Бот не должен запирать человека в разговоре с машиной, но клиенту важно разгрузить операторов.
**Варианты:** а) сразу (предлагаем); б) сначала ответ по правилам, обращение — при повторной просьбе; в) только по решению бота.
**Пока делаем так:** Прямая просьба — это «оператор»; типовой вопрос из того же сообщения бот закрывает частичным ответом. На «ты человек?» честно отвечает, что он бот.
**Если ответ другой:** Правило в промпте с учётом истории и перепрогон.

### 10. Приветствие, тон и служебные сообщения
**Вопрос:** Есть ли готовый текст приветствия или гайд по тону бренда? Наш вариант: на «вы», без канцелярита и эмодзи, бот честно называет себя ботом.
**Почему важно:** Первое сообщение задаёт ожидания и предупреждает о мошенниках (11.2); на «привет» и «спасибо» бот должен отвечать без обращения.
**Варианты:** а) наш вариант; б) ваш текст или гайд; в) персонаж бренда.
**Пока делаем так:** На /start — статичный текст из кода: что умеет бот, часы операторов (12.1), сайт (1.4), предупреждение про карты, пароли и коды (11.2). На приветствия, «спасибо», «ты бот?» — короткий служебный ответ без пунктов и обращения, вне статистики вопросов.
**Если ответ другой:** Меняются текст и абзац о тоне в промпте, перепрогон.

### 11. Чеки, не проверенные к последнему еженедельному розыгрышу
**Вопрос:** Чеки от 26.10–01.11, не проверенные к 12:00 03.11, участвуют только в главном розыгрыше? Что с чеком, который перенесли по 8.1, но не проверили и к следующей отсечке?
**Почему важно:** 8.1 переносит чеки в «следующий еженедельный», а 03.11 — последний (2.4). Чек от 29.10 могут проверить 03.11 после 12:00, от 30.10–01.11 — до чт 05.11 (04.11 — выходной); это пик регистраций.
**Варианты:** а) только главный 10.11 (8.3); б) дополнительный еженедельный розыгрыш; в) модерация гарантированно успеет.
**Пока делаем так:** Бот не обещает участие 03.11; после него еженедельных нет, принятый чек участвует в главном (8.3). Повторный перенос — оператору.
**Если ответ другой:** Меняются строка календаря в коде и ответ бота.

### 12. «Сутки» в лимите 10 чеков
**Вопрос:** «Не более 10 чеков в сутки» (6.1) — календарные сутки по МСК или 24 часа с первой регистрации?

**Варианты:** а) календарные сутки по МСК; б) скользящие 24 часа.
**Пока делаем так:** Бот повторяет правило без толкования, время сброса не называет; «когда обнулится лимит» — оператору.
**Если ответ другой:** Добавим уточнение, бот ответит сам.

### 13. Смена номера телефона
**Вопрос:** Можно ли сменить номер в аккаунте (например, при потере SIM)? Кто это делает и как проверяет, что пишет владелец?
**Почему важно:** Это №14. Процедуры нет, 5.2 привязывает участника к номеру; без кабинета победитель может не успеть подтвердить приз за 3 календарных дня (9.2); смена номера из чата — путь к захвату аккаунта.
**Варианты:** а) меняет оператор — какие данные для проверки?; б) техподдержка сайта; в) нельзя.
**Пока делаем так:** Бот передаёт оператору, просит старый и новый номер, ничего не обещает, напоминает про 11.2; в сводке — срочность и проверка личности.
**Если ответ другой:** Бот отвечает по уточнению; меняется эталон для №14.

### 14. Фасовки и мультипаки
**Вопрос:** Участвуют ли йогурты тех же линеек в другой фасовке (например, питьевой 900 г)? Мультипак одной строкой («Краюшка» 4×100 г) — 1 единица или 4?
**Почему важно:** 4.1 называет линейки с весом, 5.5 считает шансы по единицам; это понадобится и для оценки фото чеков.
**Варианты:** а) другие фасовки не участвуют, мультипак — по числу йогуртов; б) мультипак — одна единица; в) участвуют все фасовки.
**Пока делаем так:** Бот отвечает буквально по 4.1, по мультипакам шансы не считает — решает модерация; конкретный случай — оператору.
**Если ответ другой:** Добавим уточнение, бот посчитает сам.

### 15. Время покупки: часовой пояс и заказы с доставкой
**Вопрос:** Засчитывается ли чек с местным временем 23:30 31.10 из Калининграда (00:30 01.11 по МСК)? Какая дата считается датой покупки для заказа с доставкой — заказа, оплаты или чека?
**Почему важно:** Всё время в правилах — МСК (1.5), а в чеке — местное; заказ от 31.10 с доставкой 01.11 может выпасть из 2.2.
**Варианты:** а) время в чеке, пересчитанное в МСК; б) местное время; в) решает модерация.
**Пока делаем так:** Бот пишет сроки по МСК, при вопросе пересчитывает по 1.5, исход не обещает; спорное — оператору.
**Если ответ другой:** Добавим уточнение, бот ответит однозначно.

### 16. Налоги и главный приз
**Вопрос:** Можно ли называть ставку НДФЛ и сумму денежной части главного приза? Покрывает ли удержание (10.2) налог, если у победителя есть и еженедельные призы? Как и когда вручается сертификат на путешествие?
**Почему важно:** Правила дают порог и порядок (10.1–10.3), но не ставку и не сумму (7.2); вручение главного приза описано только 9.1–9.3 и сроком 2.6. Модели подставляют ставку из внешних знаний.
**Варианты:** а) не называем, вопросы — оператору (предлагаем); б) пришлёте формулировки.

### 20. Несколько операторов и очередь
**Вопрос:** Сколько операторов будет в панели, нужно ли закреплять обращение за оператором и подписывать ответы именем?
**Почему важно:** Без закрепления двое могут ответить одному участнику одновременно.
**Варианты:** а) общая очередь без закрепления (предлагаем); б) «Взять в работу»; в) роли оператора и старшего.
**Пока делаем так:** Свои учётные записи (создаёт команда), общая очередь (старые сверху), в карточке видно, кто ответил, у ответа хранится автор; участнику — «Ответ оператора:» без имени.
**Если ответ другой:** Поле «назначен» и кнопка; статистика по операторам — группировка по автору.

### 21. Жалобы с угрозами
**Вопрос:** Жалобы с угрозами (Роспотребнадзор, суд, СМИ) выделять в очереди или сразу передавать кому-то со стороны клиента?
**Почему важно:** Это №21 — репутационный риск для бренда.
**Варианты:** а) пометка «Жалоба» (предлагаем); б) в начало очереди; в) уведомлять менеджера клиента.
**Пока делаем так:** Обычное обращение, суть начинается со слова «Жалоба:»; бот отвечает спокойно, даёт 6.4 и 6.5 и передаёт.
**Если ответ другой:** Признак срочности в JSON модели и сортировка очереди.

### 22. Закрытие обращения
**Вопрос:** Сообщать ли участнику о закрытии обращения? Нужно ли автозакрытие, если участник молчит после ответа?
**Почему важно:** Без уведомления участник не знает, что вопрос решён; без автозакрытия новые вопросы дописываются в старое обращение.
**Варианты:** а) короткое сообщение, без автозакрытия (предлагаем); б) молча; в) просить оценку 1–5.
**Пока делаем так:** «Обращение закрыто. Если остались вопросы — просто напишите сюда». Закрывает только оператор.
**Если ответ другой:** Поле оценки и строка в статистике; автозакрытие — задача по расписанию.

### 23. Фото, голосовые, стикеры и файлы
**Вопрос:** Что делать с фото, голосовыми, стикерами и файлами, пока бот не умеет их разбирать?
**Почему важно:** Участники пришлют фото чеков, а организатор сам может запросить фото оригинала (6.6).
**Варианты:** а) при открытом обращении — прикреплять, иначе просить текст (предлагаем); б) всегда «понимаю только текст»; в) любое фото — оператору.
**Пока делаем так:** Подпись к фото — как текст; фото и документ при открытом обращении прикрепляем (file_id); остальное — ответ кода «Пока я понимаю только текст — опишите вопрос словами», вне статистики.
**Если ответ другой:** Б проще, но фото придётся принимать по почте; в — больше обращений.

### 24. Вопросы о продукции и офтоп
**Вопрос:** Как отвечать на вопросы вне акции: рецепты, состав, где купить, жалобы на качество? Нужен ли боту контент бренда?
**Почему важно:** Это №23. Без согласованного контента бот будет выдумывать (в том числе про детское питание), а жалобу на качество нельзя закрывать отказом.
**Варианты:** а) рецепты и состав — отказ, жалобы — оператору (предлагаем); б) ответы по контенту бренда; в) отказ со ссылкой на ресурсы бренда.
**Пока делаем так:** Рецепты и состав — вежливый отказ без обращения; «где купить» — ответ по 1.3; жалоба на качество — оператору.
**Если ответ другой:** Источник контента, отдельный тип ответа, перепрогон.

### 25. Мат, оскорбления и повторные попытки взлома
**Вопрос:** Нужно ли кроме спокойного ответа предупреждать, игнорировать или блокировать за мат, оскорбления и повторные попытки взлома?
**Почему важно:** Это №21, 24, 25; фильтр мата — на потом, но вопрос по существу терять нельзя.
**Варианты:** а) без блокировок (предлагаем); б) предупреждение, потом пауза; в) блокировка и пометка в панели.
**Пока делаем так:** Бот не отвечает грубостью и отвечает по существу; чистые оскорбления и манипуляции — вежливый отказ без обращения; «я сотрудник / админ» ничего не меняет.
**Если ответ другой:** Поле у участника и порог отказов за период.

### 26. Сообщения не на русском
**Вопрос:** Отвечать ли на языке участника, если он пишет не по-русски?
**Почему важно:** Акция для граждан РФ (3.1), правила и операторы — на русском.
**Варианты:** а) всегда по-русски (предлагаем); б) на языке участника.
**Пока делаем так:** Модель понимает любой язык и транслит, отвечает по-русски; суть для оператора — по-русски.
**Если ответ другой:** Одна строка в промпте и перепрогон.

### 27. Хранение переписки и удаление данных
**Вопрос:** Сколько хранить переписку и данные участников (телефоны, ФН, суть обращений)? Как в 11.1, до 31.12.2027? Что делать с запросом на удаление?
**Почему важно:** В переписке персональные данные; согласие по 11.1 даётся на сайте, а в бот может написать незарегистрированный человек.
**Варианты:** а) до 31.12.2027 (как 11.1); б) короче; в) по политике клиента.
**Пока делаем так:** Храним до 31.12.2027, затем удаляем командой (расписание — в README «перед продом»), статистику сохраняем обезличенной; запрос на удаление — оператору с частичным ответом по 11.1.
**Если ответ другой:** Меняется дата в команде очистки.

### 28. Маскирование и внешний ИИ
**Вопрос:** Маскировать ли кроме карт телефоны, e-mail и паспортные данные хотя бы перед отправкой в ИИ? Можно ли отправлять тексты участников в Gemini (сервис за рубежом)?
**Почему важно:** Это трансграничная передача персональных данных (152-ФЗ); телефон модели для решения не нужен.
**Варианты:** а) только карты (предлагаем для пилота); б) телефоны и e-mail — метками только в запросе к ИИ; в) провайдер с серверами в РФ.
**Пока делаем так:** Маскируем только карты (13–19 цифр с пробелами, в том числе неразрывными, дефисами и точками) до базы, логов, очереди и ИИ; ФН, ФД, ФП, РН ККТ и телефоны не трогаем; риск описан в README.
**Если ответ другой:** Б — пара регулярных выражений; в — замена клиента ИИ.

### 29. Интеграция с сайтом акции
**Вопрос:** Есть ли у сайта API для статусов чеков, победителей и доставки? Для MVP считаем, что нет.
**Почему важно:** С API бот сам отвечал бы на самые частые вопросы к операторам (№16, 17, 18, 21, 22).
**Варианты:** а) нет (предлагаем); б) есть — пришлём документацию; в) появится позже.
**Пока делаем так:** Интеграции нет, такие вопросы — оператору; в README — как доработка.
**Если ответ другой:** Нужна надёжная привязка Telegram к аккаунту, иначе бот раскроет чужие статусы по чужому номеру.

### 30. Обращения по e-mail
**Вопрос:** Письма на support@vkusnaya-osen.example (12.1) в панель не попадают. Для пилота это нормально?
**Почему важно:** В правилах два канала поддержки.
**Варианты:** а) только Telegram (предлагаем); б) подтягивать почту в очередь.
**Пока делаем так:** Панель работает только с Telegram-ботом.
**Если ответ другой:** Приём почты (IMAP) и поле «канал» у обращения.
