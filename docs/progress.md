## На что обратить внимание разработчику

1. **Квота Gemini — главный риск.** Ключ на бесплатном тарифе: ~20 запросов в сутки на модель (`GenerateRequestsPerDayPerProjectPerModel-FreeTier`), сброс в 10:00 МСК. Один прогон 25 обращений расходует квоту двух моделей, поэтому в `GEMINI_MODELS` цепочка из 7 моделей и часть ответов в прогоне даёт более слабая модель (`gemini-3.6-flash`, `gemini-3.5-flash-lite`…). Для доработки промпта и для сдачи нужен ключ с нормальной квотой: платный тариф или ключ от работодателя (`task.md`: «выдадим ключ с лимитом»). С таким ключом верните `GEMINI_MODELS=gemini-3.8-flash,gemini-3.5-flash` и прогоните `bot:eval` заново.
2. **Сессии для сдачи.** Экспортировать `/export` нужно вам: эту сессию (шаги 0–5, самая важная) и сессию шага 0 (анализ). Перед коммитом экспортов — `grep` по токену и ключу.
3. **Вопросы менеджеру** по-прежнему не отправлены (8 критичных, текст в `docs/questions-for-manager.md`).
4. **Telegram-плагин Claude Code** в этой сессии не подключался и поллеру не мешал. Если включите его с тем же токеном, бот перестанет получать сообщения (409).
5. **Ваш `.env`:** `GEMINI_MODELS` заменён на цепочку из 7 моделей; `GEMINI_MODEL` и `GEMINI_FALLBACK_MODEL` не используются, можно удалить.

## Решения

| Решение | Кто решил | Почему |
|---|---|---|
| Запуск для проверяющего: `cp .env.example .env`, два ключа, `docker compose up`. Остальное делает контейнер | разработчик | Проверяющий вписывает свои ключи, процесс должен быть минимальным |
| Модели Gemini — список `GEMINI_MODELS`, при любом сбое пробуем следующую (более слабую) | разработчик | «Можно пробовать вызывать более слабые модели» |
| Панель — Blade и немного JS, без Filament, Livewire и npm | агент | Меньше сюрпризов с версиями, не нужна сборка фронта |
| При открытом обращении бот сам отвечает на типовые вопросы, остальное дописывает в обращение | агент | Задача клиента — разгрузить операторов. Вопрос №3 менеджеру |
| Часы прогона — вт 06.10.2026 10:00 МСК, параметр `--now` | разработчик | День розыгрыша до отсечки; с этой датой сходятся №16 и №22 |
| Действия модели: `answer`, `operator`, `refuse`, `smalltalk` | агент | Иначе «спасибо» уйдёт оператору по правилу «ответ без пунктов → оператор» |
| Без очереди и worker: poller обрабатывает сообщения сам | агент | Путь наименьшего сопротивления |
| Тесты на Postgres (БД `testing`), не на SQLite | агент | Стек из ТЗ — Postgres; тест на сдвиг времени имеет смысл только на нём |
| Маскирование карт — буквально по правилу разработчика (13–19 цифр), ФН не трогаем. Телефон с числом подряд («8 910 123 45 67 10 чеков») — известная проблема | агент | Не усложнять; случай записан в README |
| Фото при открытом обращении — пометка «[фото]», картинку оператор не видит | агент | Просмотр фото — доработка; в README «Известные проблемы» |
| Вопросы менеджеру поделены: 8 критичных (отправить), 22 для протокола | разработчик | Отправлять только то, что влияет на реализацию |
