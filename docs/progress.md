С ключом нормальной квоты (платный тариф или ключ от работодателя: в `task.md` обещают «выдадим ключ с лимитом») поставить `GEMINI_MODELS=gemini-3.8-flash,gemini-3.5-flash` и прогнать заново: `docker compose exec web php artisan bot:eval`, прочитать ответы в `docs/eval/<дата>.md`, поправить оценки в `docs/eval/tools/verdicts.py` и пересобрать таблицу командой `python docs/eval/tools/make_report.py docs/eval/<дата>.md docs/eval/tools/verdicts.py docs/eval-report.md`.

6. **Оценка №20 «неверно»** выставлена по букве шкалы (запрещённое эталоном утверждение). Если решите смягчить до «спорно», поменяйте `N` на `S` в `docs/eval/tools/verdicts.py` и пересоберите таблицу командой из п. 4, затем поправьте цифры в README и здесь.

## Решения

| Решение | Кто решил | Почему |
|---|---|---|
| Запуск для проверяющего: `cp .env.example .env`, два ключа, `docker compose up`. Остальное делает контейнер | разработчик | Проверяющий вписывает свои ключи, процесс должен быть минимальным |
| Модели Gemini — список `GEMINI_MODELS`, при любом сбое пробуем следующую (более слабую) | разработчик | «Можно пробовать вызывать более слабые модели» |
| Панель — Blade и немного JS, без Filament, Livewire и npm | агент | Меньше сюрпризов с версиями, не нужна сборка фронта |
| При открытом обращении бот сам отвечает на типовые вопросы, остальное дописывает в обращение | агент | Задача клиента — разгрузить операторов. Вопрос №3 менеджеру |
| Часы прогона — вт 06.10.2026 10:00 МСК, параметр `--now` | разработчик | День розыгрыша до отсечки; с этой датой сходятся №16 и №22 |
| Действия модели: `answer`, `operator`, `refuse`, `smalltalk` | агент | Иначе «спасибо» уйдёт оператору по правилу «ответ без пунктов → оператор» |
| Без очереди и worker: poller обрабатывает сообщения сам | агент | Путь наименьшего сопротивления |
| Тесты на Postgres (БД `testing`), не на SQLite | агент | Стек из ТЗ — Postgres; тест на сдвиг времени имеет смысл только на нём |
| Маскирование карт: 13–19 цифр подряд, кроме мобильных номеров и реквизитов чека (ФН, ФД, ФП, ККТ); проверки Луна нет | агент | Телефон — ключ к кабинету, ФН нужен оператору; остальное записано в README как эвристика |
| Фото: хранится только `telegram_file_id`, панель подгружает картинку из Telegram по запросу; модель фото не видит, в неё идёт только подпись | разработчик и агент | Оператору нужно видеть чек; картинка вне модели — защита от инъекций через текст на фото |
| Оценка решения бота хранится в самом решении: одна оценка, последняя побеждает | агент | Оценивается решение, а не диалог; история правок для пилота не нужна |
| Таблица для сдачи — по итоговому прогону; проверочный прогон при исчерпанной квоте её не заменяет | разработчик | Таблица должна отражать прогон на нормальных моделях, а не на остатке квоты |
| Вопросы менеджеру поделены: 8 критичных (отправить), 22 для протокола | разработчик | Отправлять только то, что влияет на реализацию |
| Оценки таблицы прогона пересмотрены по букве шкалы (14 / 10 / 1 вместо 20 / 5 / 0); шкала и эталон не менялись | агент, на финальной проверке | Два независимых скептика подтвердили, что в шести строках «верно» нет обязательных элементов эталона; честные цифры важнее красивых, проверяющие оценивают честность |
| Скилл `code-council` лежит в `.claude/skills/code-council/` и входит в репозиторий | агент | Проверяющие оценивают процесс работы с агентом; скилл — часть финальной проверки |

## План шагов

Все шаги 0–5 выполнены; шаг 6 — по команде разработчика. После каждого шага: тесты → коммит (без push) → короткий отчёт разработчику → обновить этот файл.

1. **Каркас и база** (~2–2,5 ч). Dockerfile, `compose.yaml` (postgres, web, bot), скелет Laravel 13, entrypoint (APP_KEY, migrate, seed), `.env.example`, миграции 4 таблиц акции и стандартная `users`, модели, `PromoClock`, тесты: `/up`, оператор из `.env`, инварианты БД, сдвиг времени. Готово, когда `docker compose up` с чистого клона поднимает панель.
2. **Ядро бота и первый прогон** (~2,5–3,5 ч). Промпты в `resources/prompts/`, `GeminiClient` со списком моделей, `RulesRepository`, `DrawCalendar`, `CardMasker`, `DecisionEngine` с проверкой пунктов, `bot:eval` с `--now` и сверкой с эталоном. Готово, когда отчёт прогона закоммичен.
3. **Telegram** (~1–1,5 ч). `TelegramClient`, `bot:poll`, дубли, `/start`, сообщения без текста, обращения, фраза о сроке. Готово, когда бот отвечает в живом чате.
4. **Панель** (~2,5–3,5 ч). Вход, очередь, обращение с историей и текстами пунктов, ответ, закрытие с уведомлением, решения бота, статистика.
5. **Сдача** (~2–3 ч). Правка промпта по прогону (`docs/prompt-changelog.md`), README, таблица прогона `docs/eval-report.md`, запуск с чистого клона, экспорт сессий и grep на секреты.
6. **Публикация** — только по команде разработчика.
