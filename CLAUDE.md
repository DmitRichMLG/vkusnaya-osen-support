# CLAUDE.md — бот поддержки «Вкусная осень»

Тестовое задание на ИИ-инженера (M-Social). Нужно сделать Telegram-бота поддержки для промо-акции йогуртов и веб-панель операторов. Бренд, акция и все данные вымышлены.

## Источники истины

| Файл | Что это |
|---|---|
| `docs/assignment/task.md` | Задание работодателя. Что сдаём и как оценивают |
| `docs/prompt.txt` | Постановка разработчика для агента. Главный документ о поведении бота и о процессе работы |
| `docs/assignment/promo-rules.md` | Правила акции. Единственный источник, по которому отвечает бот |
| `docs/assignment/requests.md` | 25 обращений для прогона |
| `docs/expected-answers.md` | Эталон: что бот должен сделать с каждым из 25 обращений. По нему сверяет прогон |
| `docs/questions-for-manager.md` | Вопросы менеджеру и временные допущения, пока нет ответа |
| `docs/design.md`, `docs/db-schema.md` | Архитектура и схема БД (черновик на согласовании). Раздел «Упрощения для MVP» в начале `design.md` важнее остального текста |

## Стек и принятые решения

- PHP 8.4 + Laravel 13, PostgreSQL. Всё работает в Docker, запускается одной командой `docker compose up`. Локально PHP и Composer не нужны.
- Панель операторов: обычный Blade и немного JS. Без Filament, Livewire и npm-сборки — путь наименьшего сопротивления.
- Telegram: long polling без вебхука. Bot API вызываем через HTTP-клиент Laravel, без SDK.
- LLM: Gemini. Модель берётся из `GEMINI_MODEL`, при 503 переключаемся на `GEMINI_FALLBACK_MODEL`. Ответ модели — строго JSON: действие, текст, суть для оператора, номера пунктов.
- При прогоне обращений часы заморожены на 2026-10-06 10:00 МСК. Для другой даты есть параметр `--now`.
- Пока у участника открыто обращение, бот сам отвечает на типовые вопросы, а всё, что требует оператора, дописывает в это обращение. Это временное допущение, вопрос отправлен менеджеру.

## Как работаем

1. Идём по шагам (план — `docs/design.md`, раздел «План реализации»). Шаг — небольшой законченный кусок: код → тесты → коммит → короткий отчёт разработчику (что сделано и что решил сам). После шага 0 (анализ без кода) ждём согласования, дальше не идём.
2. Если решаешь сам то, о чём не договаривались, скажи об этом разработчику и запиши в README → «Допущения».
3. Там, где ТЗ молчит, добавь вопрос в `docs/questions-for-manager.md` и временное допущение.
4. Не пушь, пока не попросят.

## Обязательно при изменениях

- **Поменял промпт бота** → прогони все 25 обращений заново (`bot:eval`), обнови таблицу прогона и опиши в README, где бот ошибался и что поменяли.
- **Поменял базу (миграции)** → обнови `docs/db-schema.md`: mermaid-диаграмму и раздел «почему так».
- **Поменял поведение бота** → сверь с `docs/expected-answers.md`. Эталон меняем только осознанно, с пометкой, почему.
- **Что-то не доделал или нашёл ограничение** → запиши в README → «Известные проблемы».
- **Принял новое допущение** → запиши в README → «Допущения».
- **Перед коммитом** тесты должны быть зелёными.

## Нельзя

- Класть секреты (`.env`, токены, ключи) в репозиторий, логи или чат. `.env` лежит в `.gitignore`, в репозитории только `.env.example` без значений.
- Логировать URL запросов к Telegram: в них есть токен бота. Сюда же относятся тексты исключений с такими URL.
- Хранить номера карт в открытом виде. Маскируем их до записи в БД, в очередь и логи и до отправки в ИИ. ФН чека и телефоны не маскируем.
- Выдумывать ответы. Бот отвечает только по правилам и ссылается на существующие пункты, иначе передаёт вопрос оператору. Если ИИ сломался, вопрос всё равно уходит оператору.
- Считать даты в модели. Текущую дату и календарь розыгрышей считает код. Время храним в timestamptz (UTC), в МСК переводим при показе и при расчёте сроков и розыгрышей — только через один класс времени, без `whereDate`.
- Выводить секреты в консоль: не запускать `env`, `printenv`, `config:show services|app`, не читать `.env` целиком. Перед коммитом экспортов сессий — `grep` по шаблонам токена и ключа.
- Запускать второй poller с тем же токеном (Telegram ответит 409, бот перестанет получать сообщения).

## Ловушки окружения

- Файлы задания и все файлы из Windows могут быть в CRLF. Всё, что код читает (правила, обращения, эталон, промпты), приводим к LF до разбора и хеширования. В репозитории всё хранится в LF (`.gitattributes`).
- Docker Desktop работает поверх WSL2; локального PHP нет, команды `php`/`composer` — только через `docker compose`.
